# Variation axes

| Axis | Values | Variation |
| --- | --- | --- |
| Readability | read, low_confidence, unreadable | The variation in this axis comes from legibility of the handwriting from the user. This could include poor handwriting, poor scan quality of the document, or struckthrough/scribbled out text. |
| Document Orientation | 0-360 degrees | The document can be oriented in any direction relative to the standard landscape format. |
| Document Scale | 0.75x-1x | The timesheet could be submitted as an image with variation in the scale relative to a scanned document. A 1x scale document is an image where the entire bounds of the image are the timesheet, where a 0.4x scale image is scaled such that 40% of the image area is the timesheet. |
| Document Perspective | 0-25 degrees | This axis is the relative angle of the timesheet to the perspective of the camera. Zero degrees would be perfectly flat, where 25 degrees represents a 25 degree angle of the timesheet page relative to the camera. |
| Template Content | N/A | The template can contain an infinitely variable set of content across each of the fields. The generated text and handwriting should feature names that look real and pay rates/hours across a statistically probable distribution based on real labor and pay statistics. Pay types should also be varied based on the set defined in the template. |

## Important Note
My data arrives as a scanned document with handwritten fields from the client. The data in my golden.jsonl file was extracted by me from a synthetic set of timesheets generated by claude to avoid leaking PII. I am adding the variation axes to this file with the understanding that I will have to use claude to generate additional synthetic payroll timesheet images that capture the variation I have defined.
